### 分类规则与阅读方式

1. **项目关系：**Dynamo-only、llm-d-only、两者都明确提及、均未明确提及。只依据官方标题／摘要，大小写不敏感；不根据讲者公司、赞助商、房间名称或展位信息推断。**vLLM ≠ llm-d，NIXL ≠ Dynamo，KAI Scheduler ≠ Dynamo。**
2. **技术主题：**服务编排／生命周期；路由与流控；P/D／KV cache／存储；GPU／拓扑／共享；观测／成本／弹性／评估；边缘／可移植性。Agent、训练、通用设备管理等邻接议程单列，不混入核心推理数量。

4. **证据边界：**摘要中的“GA”“1.0”“production-grade”、部署客户、性能倍数及成本节省均为讲者陈述，未独立验证，也不代表本报告核验了对应 release／benchmark。以下 AKS／KAITO 启示是分析建议，不是 Azure 产品支持声明。

### 明确提及 Dynamo 的 2 场

#### [The RCA Bot Needed an RCA: Compute Confidence, Don't Generate It](https://events.linuxfoundation.org/kubecon-cloudnativecon-north-america/co-located-events/cncf-hosted-co-located-schedule/?id=1269543)

**10:40–11:05 MST · 251 D-F · Madhu Patel、Sudhanshu Sah**

围绕自动 RCA 的可信度，把候选根因的 token 概率、校准与 conformal prediction 组合成可计算的置信结果，并在 Agent Sandbox 的 Firecracker microVM 中验证可疑原因。**关系证据：**摘要明确写道 “serve the traffic this creates with NVIDIA Dynamo”，具体包括 cache-first routing、路由器可感知的 CPU 缓存层及按严重性设置请求优先级。**AKS／KAITO 启示：**可参考缓存亲和与优先级服务设计，但这是应用驱动的 Dynamo 使用案例，不是 KAITO 集成说明；摘要所称后续请求快 12 倍、microVM 不到一秒等均为讲者数据。

#### [Beyond Shipping the Model: Making Inference Boringly Repeatable](https://events.linuxfoundation.org/kubecon-cloudnativecon-north-america/co-located-events/cncf-hosted-co-located-schedule/?id=1269619)

**13:30–13:55 MST · 251 D-F · Prithvi Raj**

把数百模型、异构硬件和不同引擎的推理交付视为平台抽象问题：将硬件 profile、引擎选择、自动调优和部署拓扑固化为可复用原语，而非让每个团队依赖性能专家。**关系证据：**Dynamo 仅出现在引擎列举 “vLLM, SGLang, TensorRT-LLM, Dynamo” 中，因此应称“明确提及 Dynamo 的多引擎平台报告”，不能包装成 Dynamo 深度实战。**AKS／KAITO 启示：**适合讨论把模型与硬件经验沉淀为声明式配置、模板及选择策略，减少逐团队手工配置，但摘要没有给出 KAITO 或特定云集成。

### 明确提及 llm-d 的 5 场

#### [llm-d Observability: Observing LLM Inference at Scale on Kubernetes](https://events.linuxfoundation.org/kubecon-cloudnativecon-north-america/co-located-events/cncf-hosted-co-located-schedule/?id=1262963)

**11:15–11:40 MST · 251 D-F · Guangya Liu、Nicole Xin** · [幻灯片](https://sessionize.com/download/citqadi~BsvZwUeY4DtobnMXdy4kH8.pdf~seeing-through-the-stack_-end-to-end-observability-for-llm-d-kubecon-na-2026.pdf)

审计 llm-d 的网关、EPP 路由、KV indexer、vLLM worker 与 P/D sidecar 在 metrics、traces、logs、仪表盘和告警上的覆盖，重点是跨组件 trace 关联、P/D KV 传输可见性等缺口。**关系证据：**标题直接命名 llm-d，摘要还明确讨论 “llm-d Router (EPP)” 与 W3C TraceContext、OTel Collector、分层 KV 观测和 WVA 可见性。**AKS／KAITO 启示：**可作为 MultiRoleInference 运维清单：不只看 Pod/GPU，还应串起请求路由、缓存命中、P/D 传输与伸缩决策；“3x throughput gains”及“zero pre-built dashboards”是摘要的性能／当时状态陈述，不能当作已验证现状。

#### [Best Practices for LLM Autoscaling from the llm-d Ecosystem](https://events.linuxfoundation.org/kubecon-cloudnativecon-north-america/co-located-events/cncf-hosted-co-located-schedule/?id=1245135)

**14:05–14:30 MST · 254 · Jiazhou Gao、Abhishek Malvankar** · [幻灯片](https://sessionize.com/download/itladweo~BzUs4LwfWz3acW5qzSkjw4.pdf~best-practices-for-llm-autoscaling-3.pdf)

说明为什么 GPU 利用率和传统 HPA 不能充分刻画 LLM 饱和、冷启动与 KV 压力，建议结合队列深度、KV 使用、TTFT 和请求饱和度进行 workload/SLO/hardware-aware 伸缩。**关系证据：**标题及摘要均明确关联 llm-d，摘要称经验来自 “heterogeneous inference serving systems in the llm-d ecosystem”。**AKS／KAITO 启示：**可用这些信号评估 KEDA／角色独立扩缩容策略，并把模型加载时间与缓存预热纳入容量计划；这里讨论生态实践，不是单个 autoscaler 的官方完整配置指南。

#### [DRA + Kueue + HAMi + vLLM: A Production Architecture for Scheduler-Agnostic GPU Sharing](https://events.linuxfoundation.org/kubecon-cloudnativecon-north-america/co-located-events/cncf-hosted-co-located-schedule/?id=1267046)

**15:20–15:45 MST · 251 D-F · Mengxuan Li、Yuchen Fama** · [幻灯片](https://sessionize.com/download/iddayded~JuoPmTUtFpjfUt8jEp25Ej.pptx~v2-kubecon2026_-dra-kueue-hami-llm-d-inference-day-na-2026.pptx)

展示 DRA + Kueue + HAMi webhook + vLLM 的生产参考架构，目标是在不替换既有调度器的情况下提供细粒度 GPU 划分，同时讨论 DRA 监控和分配 API 的生产障碍。**关系证据：**摘要明确写道 “with llm-d handling distributed LLM inference routing on top”，即 llm-d 位于设备分配／队列机制上方，负责分布式请求路由。**AKS／KAITO 启示：**适合拆分讨论资源配额、设备划分与推理路由三层职责；采用前仍须核实目标 AKS 版本、DRA 驱动、HAMi 与 GPU 隔离条件，摘要中的 “scheduler-agnostic” 并非任意集群即插即用的兼容性保证。

#### [Prefill Here, Decode There: Kubernetes-Native LLM Inference Disaggregation with KAITO and llm-d](https://events.linuxfoundation.org/kubecon-cloudnativecon-north-america/co-located-events/cncf-hosted-co-located-schedule/?id=1263142)

#### [Your KV Cache Is Bigger Than Your GPU: Scaling Agentic Inference with Networked Storage](https://events.linuxfoundation.org/kubecon-cloudnativecon-north-america/co-located-events/cncf-hosted-co-located-schedule/?id=1264176)

### 对 AKS／KAITO 的归纳

- **最直接的实现链：**KAITO P/D 声明式编排 → llm-d 请求与 KV 感知路由 → 每角色伸缩 → 跨组件观测；不要只以 Pod Ready 或 GPU 利用率判断服务健康。
- **底层容量决定上层效果：**部署准入、DRA／队列／拓扑、CPU／NUMA、缓存生命周期和网络存储应联合评估；缓存共享与存储卸载并不自动产生净收益。
- **平台化胜过重复手工调优：**把模型／硬件 profile、引擎选择、配置验证和安全回滚转为可复用接口，同时保留性能与正确性验证。
- **明确边界：**Agent 生命周期、身份和 AI 辅助发布值得 AKS 平台团队关注，但它们不等于推理引擎或 Dynamo／llm-d 项目进展；不能把整场活动全部算成核心 inference 报告。
